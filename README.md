# Crypto Momentum Lab

Порівняння **річно-нормалізованого моментуму** топових криптовалют одразу на кількох
вікнах — щоб бачити, куди свопати і коли — плюс бектест ротації BTC ↔ альткоїни
на тому самому сигналі.

Це декомпозована переробка проєкту `Crypto Momentum`: увесь функціонал збережено,
але код розкладено по шарах і класах замість двох великих модулів і 600-рядкового
`app.py`. Рушій стратегії перевірено на побітову відповідність оригіналу.

## Швидкий старт

```bash
pip install -r requirements.txt
```

```bash
python prefetch.py --interval 2h --years 5
```

```bash
python -m streamlit run app.py
```

Команда `streamlit` без `python -m` може не працювати: Python із Microsoft Store кладе
`streamlit.exe` у `%LOCALAPPDATA%\Packages\PythonSoftwareFoundation.Python.3.12_*\LocalCache\local-packages\Python312\Scripts`,
а цей каталог не в `PATH`. `python -m streamlit` обходить це без будь-яких налаштувань.
На Windows є ще `run.ps1` — те саме одним кліком.

`prefetch.py` можна пропустити — застосунок сам довантажить дані, просто перший
запуск буде довшим.

## Як рахується моментум

Для вікна `W` днів беремо (опційно згладжену) ціну і масштабуємо приріст до року:

| Режим | Формула | Коли |
|---|---|---|
| логарифмічний (за замовчуванням) | `ln(P_t / P_{t-W}) · 365 / W` | порівняння різних вікон між собою |
| складний (CAGR) | `(P_t / P_{t-W})^(365/W) − 1` | «якби такий темп тривав рік» |

Обидва дають **% річних**, тому вікно 7 днів і вікно 1 рік лежать на одній шкалі.
Логарифмічний режим стоїть за замовчуванням не випадково: складне нарахування на
коротких вікнах дає числа на кшталт +285 000 % р.р. (рух +6 % за тиждень), і графік
стає нечитабельним. Короткі вікна в будь-якому разі дають екстремальні значення —
порівнюйте монети між собою, а не з реальною річною дохідністю.

Згладжування (`none` / `SMA` / `EMA` / `ZLEMA`, період задається в **днях**, не в барах)
прибирає шум перед розрахунком, тому перемикання інтервалу свічок не змінює сенсу
параметра. `ZLEMA` («zero-lag EMA») — це звичайна EMA, якій на вхід подано ряд із
компенсованою затримкою (`EMA(ціна + (ціна − ціна[−lag]))`, `lag = (span−1)//2`):
на локально лінійному тренді майже прибирає лаг EMA, на різких розворотах трохи
перелітає.

## Інтерфейс

* **Криві моментуму** — по одному підграфіку на кожне вікно, спільна вісь X
  (зум синхронний), усі монети як лінії. Клік по легенді вимикає монету одразу на
  всіх підграфіках; зайві вікна знімаються в бічній панелі.
* **Рейтинг** — теплокарта «монета × вікно» на поточний момент, сортована таблиця,
  історія місць у рейтингу та частка часу в лідерах.
* **Ціни** — нормовані до 100 ряди, лог-шкала.
* **Симуляція стратегії** — бектест ротації BTC ↔ альти, див. нижче.
* **Дані** — знімок, експорт CSV, стан дискового кешу.

Налаштування в бічній панелі: біржа, котирування, інтервал (1h…1d), глибина історії,
склад монет (кнопка «Топ-10 CoinGecko» тягне актуальний список без стейблкоїнів),
згладжування, набір вікон (+ власні), режим нормалізації, обрізання осі Y,
щільність точок на кривій.

## Симуляція стратегії

BTC — базовий («стабільний») актив: усі кошти за замовчуванням лежать у ньому.
Кожен альт зі списку порівнюється з BTC за одним і тим же вікном моментуму; коли
альт обходить BTC достатньо сильно, портфель відкриває в ньому позицію, фінансуючи
її з BTC.

Правило — звичайний **гістерезис** із двома порогами (навмисно, щоб не тремтіти
щоразу, як перевага коливається на пару пунктів):

* **поріг входу** (`entry_edge`) — наскільки момент альта має перевищити момент BTC,
  щоб отримати слот;
* **поріг виходу** («схожості», `exit_edge`) — коли перевага падає нижче цього рівня
  (або момент альта стає від'ємним), слот звільняється й позиція повертається в BTC.

Одночасно активних слотів під альти — **K**. Якщо кандидатів, що пройшли поріг входу,
більше за K, лишаються ті, у кого перевага над BTC найбільша. Склад активних монет
тому змінюється з часом сам, без ручного втручання. Розмір позиції рахується одним
із двох способів (`Sizing`):

* **`incremental`** (за замовчуванням у UI, «подієвий») — жодного розкладу: сигнал
  перевіряється щобару, торгується лише коли він змінився. Новий вхід бере
  **поточний BTC-баланс / кількість вільних слотів у цю мить**, тому при K=3 перший
  вхід із чистого BTC забирає 33 %, другий (лишилось 2 вільних) — 50 % від залишку,
  третій — усе, що залишилось. Уже відкриті позиції ніхто не чіпає й не
  перебалансовує.
* **`target_weight`** — на кожному чекпоінті (`rebalance_days`) усі активні позиції
  примусово підганяються під фіксовану частку **1/K усього портфеля**, навіть уже
  відкриті. Це ближче до класичного періодичного ребалансу і дає суттєво більше угод.

Угоди виконуються тільки як BTC↔альт (ніколи альт↔альт напряму), по ціні закриття
бару без прослизання; комісія (в базисних пунктах) береться за кожну таку ногу.
Результат порівнюється з простим утриманням 100 % BTC за той самий період — графік
капіталу, чистий приріст понад холд, просадка, розподіл портфеля в часі та журнал
угод з CSV-експортом.

### Ротація слотів

Коли в пулі більше монет, ніж слотів K, вже відкрита позиція за замовчуванням
тримається, доки не впаде нижче порогу виходу сама по собі — навіть якщо поза
слотами є набагато сильніший моментум. `rotation_margin` (лише для `incremental`)
це вимикає: кандидат ззовні, який уже пройшов **поріг входу** і випереджає
найслабший зайнятий слот більш ніж на цю маржу, витісняє його (продаж у BTC →
купівля кандидата з BTC). Маржа існує з тієї ж причини, що й поріг виходу: без неї
дві майже однакові монети мінялися б місцями щобару й торгували на чистому шумі.

### Ранній вихід у BTC

Згладжування + вікно моментуму вносять затримку: до моменту, коли перевага альта
над BTC фактично впаде нижче порогу виходу, розворот часто вже стався. Розділ
«⏱ Ранній вихід у BTC» додає два **необов'язкові** прискорювачі (за замовчуванням
вимкнені — поведінка тоді точно як без них). Обидва лише наближають повернення в
BTC: поки умова тримається, альт примусово в BTC і не може зайти назад того ж бару,
але **чистий сигнал входу вони не відкладають** і позицію довше за звичайний
гістерезис не тримають.

* **Прогноз перетину** (`forecast_horizon_days`, `slope_window_days`) — через останні
  N днів переваги альта над BTC (`diff = момент[альт] − момент[BTC]`) проводиться
  МНК-пряма й продовжується лінійно. Якщо `diff` ще над порогом виходу, але ця пряма
  (з від'ємним нахилом) перетне поріг протягом горизонту — вихід зараз. Це «дотична
  до кривої моментуму → точка зустрічі з порогом», тобто похідний член на правилі
  виходу.
* **Вето швидкого вікна** (`fast_window_days`) — `diff` і власний момент альта
  перераховуються на коротшому вікні; якщо швидший зріз уже втратив перевагу
  (`diff ≤ поріг виходу` або швидкий момент ≤ 0), позиція закривається, навіть коли
  повільне вікно ще тримає.

`PerformanceReport.early_exits()` оцінює кожен ранній вихід постфактум:
**виправданий** — якщо повільне правило все одно вийшло б у межах горизонту;
**передчасний** — якщо перевага відновилась. Таблиця з розбивкою показується під
журналом угод.

заповнюються forward-fill не більше ніж на добу. Обсяг: 5 років × 4h × 10 монет
≈ 110 тис. барів (кілька МБ), на 1h — ×4.

## Використання як бібліотеки

```python
from momentumlab import MarketDataLoader, MomentumCalculator

loader = MarketDataLoader(exchange="binance", quote="USDT", interval="4h")
matrix = loader.close_matrix(["BTC", "ETH", "SOL"], start="2021-01-01")

panel = MomentumCalculator("4h", smoothing="EMA", smoothing_days=7).panel(
    matrix.prices, [7, 30, 90, 365])
print(panel.snapshot().round(1))
```

```python
from momentumlab import Backtester, PerformanceReport, StrategyConfig

config = StrategyConfig(base="BTC", window_days=20, entry_edge=15, exit_edge=0,
                        max_active=2, sizing="incremental")
result = Backtester(config, "4h").run(matrix.prices)
print(PerformanceReport(result).summary().round(2))
```

## Обмеження

* Монети з короткою історією (нові лістинги) просто починаються пізніше — NaN до
  першої свічки; позиція в них не відкривається, доки немає валідного моментуму.
* Прослизання й глибина стакана не моделюються — тільки комісія за ногу.
* Це дослідницький інструмент, а не інвестиційна порада.
